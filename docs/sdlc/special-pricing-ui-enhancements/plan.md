# 特殊计价（峰谷/阶梯）前端视觉与交互重构 — 方案建议

## 1. 现状审视与视觉缺陷分析

结合当前实现后的实际渲染效果（见用户反馈截图），现存的表格化内嵌方案虽然解决了信息缺失问题，但在视觉美学和人机交互上存在显著缺陷：

### 缺陷 1：表头折行拥挤（严重破坏专业度）
- **现象**：卡片宽度固定（约 750px~840px），横向强行平铺 6 列时，单列空间仅剩 80~100px。
- **恶果**：表格中 `输出 / 1M` 被迫折行为两行（`输出 /` 上、`1M` 下），`状态 / 档位` 折行为两行（`状态 /` 上、`档位` 下）。
- **影响**：破坏了整个开发工具 UI 的规整感，视觉体验极其局促生硬。

### 缺陷 2：价格数字“双轨制”重复展示（信息严重冗余）
- **现象**：第一行的 3 个标准输入框已清晰呈现了日间高峰基准价（`0.3` / `0.006` / `1.2`）；紧接着下方的表格第二行（其余日间时段）又**一模一样**地把这 3 组数字再列了一遍。
- **心理认知**：用户第一眼会产生困惑——“上面已经有了价格输入框，下面又来一个表格，我到底该看哪个？它们有什么区别？”

### 缺陷 3：货币符号过度重复（排版噪点严重）
- **现象**：表格内每个价格数字单元格均带有粗体 `CNY` 前缀（`CNY 0.15`、`CNY 0.003`、`CNY 0.6` 等），两行总计重复印制了 6 次 `CNY`。
- **影响**：数字本身的有效辨识度被高频重复的货币字符淹没，造成无谓的视觉噪音。

### 缺陷 4：重型数据库表格侵入，打碎表单视觉节奏
- **现象**：Heimdall 的模型编辑页本质是一个**配置表单（Form）**。在表单中央突兀地插入一块带有厚重灰底、实线边框、斑马纹行和双表头的重型 ERP 风格数据网格，与上下圆角输入框的现代质感极度脱节。
- **空间消耗**：仅为了表达两条规则（高峰 vs 低峰，或 ≤256K vs >256K），纵向却霸占了近 **140px** 高度，导致编辑一个模型就需要频繁大幅向下滚动。

---

## 2. 优化设计原则

1. **消除冗余（Single Source of Truth）**：避免在同一视图里对相同数值进行双重独立渲染；
2. **轻量收敛（Lightweight Footprint）**：将纵向高度从 140px 极致压缩至 24px ~ 48px，杜绝笨重的 ERP 网格感；
3. **彻底根治折行（No Header Wrapping）**：从布局上彻底消灭任何列头的异常断行与拥挤；
4. **原生组件语言对齐（Design Consistency）**：复用 Heimdall 已在全局成熟使用的 `SegmentedControl`（分段药丸按钮）与语义化 Badge。

---

## 3. 四套优化方案选型与对比

### 方案 1：【分段药丸与输入框联动】Segmented Tier Pills（最高推荐 ★★★★★）

#### 核心理念
**彻底取消额外的数据表格！**
让价格输入框回归其核心职能——作为统一的价格查看与承载器。
在价格行内提供一组精致的分段药丸按钮（Segmented Control），用户点击哪个档位，3 个价格输入框就实时平滑切到哪个档位的数值。

#### 布局原型
```
┌────────────────────────────────────────────────────────────────────────┐
│ Price source                                                           │
│ ┌────────────────┐ ┌─────────────────────────────────────────────────┐ │
│ │ DeepSeek     ⌄ │ │ [ 日间高峰 (基准) ]   [ 🟢 低峰半价 (当前生效) ] │ │ │ <- 分段切换胶囊
│ └────────────────┘ └─────────────────────────────────────────────────┘ │
│                                                                        │
│ Input / 1M (CNY)         Cached / 1M             Output / 1M           │
│ ┌──────────────────────┐ ┌─────────────────────┐ ┌───────────────────┐ │
│ │ 0.15                 │ │ 0.003               │ │ 0.60              │ │ │ <- 随切换实时联动
│ └──────────────────────┘ └─────────────────────┘ └───────────────────┘ │
│                                                                        │
│ 🕒 当前处于低峰期（01:00–04:00, 06:00–10:00 UTC），调用享受 5 折优惠     │ <- 单行微小轻提示 (20px)
└────────────────────────────────────────────────────────────────────────┘
```

#### 针对 Qwen 阶梯计价时的呈现
- 分段胶囊：`[ ≤ 256K 起步档 (基准) ]` `[ > 256K 超长上下文档 (+100%) ]`
- 底部微提示：`📏 单次请求输入 Token 超过 256K 时，系统将自动升档按第 2 档结算`

#### 优势评析
- **零数字冗余**：所有的价格只在输入框这一处呈现，不存在表上表下的重复认知负担；
- **空间占用极致节省**：相比现状的 140px 大表格，整体纵向仅增加约 24px 提示条，省下 80% 垂直空间；
- **交互质感好**：符合现代前沿开发者工具（如 Vercel, Linear, Raycast）的设计潮流；
- **表头绝对不折行**：完全避开了表格列宽分配难题。

---

### 方案 2：【横向双列轻量卡片条】Horizontal Diff / Tier Cards（次选推荐 ★★★★☆）

#### 核心理念
如果用户希望**无需点击切换、第一眼就能横向对比两档费率差距**，可以舍弃重型表格，改用**扁平无边框的横向对等卡片条**。

#### 布局原型
```
┌────────────────────────────────────────────────────────────────────────┐
│ Price source           Input / 1M (CNY)      Cached / 1M   Output / 1M │
│ [ DeepSeek     ⌄ ]     [ 0.30 ]              [ 0.006 ]     [ 1.20 ]    │
├────────────────────────────────────────────────────────────────────────┤
│ ┌─ ☀️ 日间高峰 (标准基准) ──────────────┐ ┌─ 🟢 低峰半价 (当前生效) ──────────┐ │
│ │ 其余日间时段 (UTC)                   │ │ 01:00–04:00, 06:00–10:00 UTC (5折) │ │
│ │ ¥0.30 入 · ¥0.006 存 · ¥1.20 出      │ │ ¥0.15 入 · ¥0.003 存 · ¥0.60 出    │ │
│ └─────────────────────────────────────┘ └────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

#### 优势评析
- **去表格化**：用两个圆角微卡片并排代替 6 列表格，视觉上平整柔和，自然融入卡片背景；
- **三段式价格聚合**：用单行 `¥0.15 入 · ¥0.003 存 · ¥0.60 出` 取代纵横交错的单元格，去除了 6 次重复打印的 `CNY` 噪点；
- **高度受控**：整体高度约 52px，对比清晰，一目了然。

---

### 方案 3：【紧凑精简 3 列表格】Slim 3-Column Micro-Table（折中方案 ★★★☆☆）

#### 核心理念
若项目规范明确要求必须保留结构化表格形式，则必须**将 6 列压缩为 3 列**，从根源上解决表头折行问题。

#### 列结构收敛方案
- **原 6 列**：`匹配时段`、`说明`、`输入`、`缓存`、`输出`、`状态`（列过多导致拥挤折行）；
- **新 3 列**：
  1. `计价条件与时段 (UTC)`：合并状态徽章与时段名称；
  2. `费率 (入 / 存 / 出 每百万 Token)`：合并为紧凑的单列三段式斜杠（如 `0.15 / 0.003 / 0.60`）；
  3. `档位说明 / 浮动`：标注说明（如 `5 折半价优惠` 或 `标准基准档`）。

#### 优势评析
- **列宽充裕**：3 列各分得约 240px 宽度，`输出 / 1M` 等表头折行问题彻底消失；
- **币种统领**：在表头统一定义 `(CNY / 1M)`，表内纯展示高亮数字，去除重复噪点。

---

### 方案 4：【悬停/气泡 Popover 明细】Popover Drawer（极致紧凑方案 ★★★☆☆）

#### 核心理念
主页面只展示标准基准价格，特殊规则收纳进可交互的弹出层中。

#### 布局原型
- 在 `Price source` 标签旁展示可交互的胶囊按钮：
  `[⚡ 峰谷优惠 (低峰5折) ⌄]` 或 `[📊 阶梯分档明细 ⌄]`
- 用户鼠标点击时，展开 Radix Popover 浮层，浮层内呈现完整的规则对照。

#### 优势评析
- **主界面 0 额外垂直高度消耗**；
- 适合未来规则档位极多（如 4~8 个阶梯阶段）的极端复杂模型。

## 5. 建议推进步骤

1. **采纳推荐**：首选 **方案 1（分段药丸与输入框联动）**。这是最符合现代化 macOS/VS Code 风格管理工具的做法，既消除了所有表格排版硬伤，又让用户可以直接在熟悉的输入框中审阅各档位具体数值。
2. **次选备份**：若倾向于同时静态呈现两组数字，推荐采用 **方案 2（横向双列卡片条）**。
3. **改动范围**：仅需微调 `gui/src/pages/vendor-editor-page.tsx` 中的子组件渲染结构，不变更后端持久化契约。
